## 1. Fundamental Boundary: Synthetic Fixtures vs. Real Benchmark Datasets

To ensure scientific integrity and prevent invalid deployment claims, VISTA-VLM permanently decouples data into two mutually exclusive categories:

### 1.1 Procedural Synthetic Regression Fixtures
- **Storage Location**: `data/synthetic_fixtures/mvtec/`, `data/synthetic_fixtures/visa/`
- **Purpose**: Fast automated testing, GitHub Actions CI verification, unit testing, API contract tests, and packaging verification.
- **Nature**: Procedural images with synthetic noise, ellipses, polylines, and simulated scratches/cracks generated deterministically via NumPy/OpenCV.
- **Non-Negotiable Constraint**: **Performance on synthetic fixtures is NOT evidence of generalization to genuine industrial inspection or factory defect detection.** Synthetic fixtures must never be submitted as empirical evidence in peer-reviewed benchmarks or customer validation reports.

### 1.2 Real Academic & Industrial Benchmark Datasets
- **Storage Location**: `data/real/mvtec_ad/`, `data/real/visa/`, `data/real/btad/`, `data/real/mpdd/`, `data/real/real_iad/`
- **Purpose**: Rigorous research benchmarking, model comparison, paper publication, and industrial qualification.
- **Nature**: Authentic high-resolution sensor images acquired under physical factory conditions with real structural, optical, and mechanical defects.
- **Non-Negotiable Constraint**: Genuine datasets must be downloaded and verified under their respective academic licenses. Synthetic data generators are **strictly forbidden from writing into or modifying `data/real/`**.

```text
│   └── synthetic/                # Generated by prepare_benchmark_data.py
│

```

## 3. Generating Procedural Synthetic Fixtures

Synthetic fixtures are prepared using `scripts/prepare_benchmark_data.py`:

```bash
# Default safe execution:
python scripts/prepare_benchmark_data.py --output-root data/synthetic_fixtures

# With custom parameters:
python scripts/prepare_benchmark_data.py \
  --output-root data/synthetic_fixtures \
  --seed 42 \
  --real-data-root data/real
```

### Safety Protections in Generator:
1. **Real-Data Rejection**: Passing `--output-root data/real` or any path inside `data/real` immediately raises `ValueError: DATA INTEGRITY VIOLATION`.
2. **Forbidden Token Check**: Any path containing tokens like `mvtec_ad`, `real_iad`, `btad`, or `mpdd` is rejected automatically.
3. **Deterministic Random Generators**: Uses `np.random.default_rng(seed)` without altering global Python/NumPy state.
4. **Dimension & Mask Verification**: Asserts $518 \times 518 \times 3$ image dimensions and strictly binary $\{0, 255\}$ masks.

## 4. Cryptographic Manifest and Leakage Verification Protocol

Before running benchmarks, datasets must be audited with `DatasetIntegrityChecker`:

```bash
python -c "
from vista_vlm.data.manifest_manager import DatasetIntegrityChecker
manifest = DatasetIntegrityChecker.build_manifest(
    dataset_name='synthetic_mvtec',
    root_dir='data/synthetic_fixtures/mvtec',
    provenance='procedural_synthetic_benchmark_fixture',
    layout='mvtec'
)
print('Manifest valid:', manifest['is_valid'])
print('Total samples:', manifest['total_samples'])
"
```

The manifest audit enforces:
1. **Zero Data Leakage**: Computes SHA-256 hashes of all images; flags an error if any test image is identical or near-duplicate to a train image.
2. **Mask Correspondence**: Verifies that every defective test image has a corresponding ground-truth mask with identical $(W, H)$ dimensions.
3. **Provenance Identification**: Every sample is explicitly tagged as `procedural_synthetic_benchmark_fixture` or `real_public_dataset`.

## 5. Configuring Real Academic Datasets

To evaluate against genuine academic datasets:
```bash
# Unpack official archives into data/real:
tar -xf mvtec_anomaly_detection.tar.xz -C data/real/mvtec_ad/

# Set root environment variable:
export VISTA_DATA_ROOT=data/real

# Execute qualification benchmark:
python scripts/run_multi_track_benchmark.py
```

If real datasets are missing, `resolve_dataset_root(dataset_key, allow_synthetic_fallback=False)` returns `real_dataset_unavailable`. The benchmark engine does **NOT** silently substitute synthetic data for real datasets.
